## Step3 機能リスト（MoSCoW・Must5個以内）
**Must**
1. ジェムパズル本体（タップ仕分け→ピクセルアート完成）
2. 完成動物の図鑑登録・なつき度育成（詳細は下記「なつき度・育成システム」）
3. 動物園ホーム画面（集めた動物が住む・眺める場）
4. スタミナ or 広告視聴によるプレイ回数制御

**Should**: 季節限定動物（LiveOps）／動物の鳴き声・生態豆知識
**Could**: フレンド動物園訪問・見せ合い／育成拡張（服・アクセサリー）
**Won't**: 対戦・ランキング要素（癒し系の世界観と不整合）

## なつき度・育成システム（差別化の核・詳細設計）
```
【段階】Lv1(出会う)→Lv2(慣れる)→Lv3(なつく)→Lv4(絆MAX・専用ポーズ解放)
【上昇条件】1日1回のタップ交流（エサ/なでる/遊ぶを日替わりでランダム提示）
【下降条件】3日未交流でLv1段階分低下（放置ペナルティ＝復帰ナッジの根拠）
【Lv4特典】専用ポーズがホーム画面に固定表示（育成実績の可視化資産）※無料機能として提供
```
- 動物ごとに性格タグ（甘えん坊／マイペース／人見知り等）を持たせ、交流時のリアクションを分岐
- 生息地カテゴリ（森/海/草原等）を3体揃えると「群れミニシーン」演出が発生（㉗㉖強化）
- Aha Moment再定義: 初回パズル完成→なつき度Lv1登録→その場で動物が1アクション（鳴く/瞬き）
- 課金は時短（交流クールタイム短縮）・見た目彩り（アクセサリー）のみ。育成の本質は無料完結

## Step3.5 グロース設計（RARRA）
### R① Retention
Aha Moment: 初回パズルで1体目完成→なつき度Lv1登録→動物アクション演出まで。
復帰トリガー: スタミナ回復通知／なつき度低下通知。ストリークでレア動物出現率UP。

### A② Activation
初回起動→Aha Moment 3タップ以内・60秒以内。アカウント作成は後回し。最初のパズルは必ず成功する簡単配色。

### R③ Referral
完成動物園のスクショ自動生成・SNSシェア（フレーム付き）。Viral Coefficient目標0.2-0.3。

### R④ Revenue
摩擦ゼロ優先（広告視聴でスタミナ回復）。課金はコスメ寄り＋サブスク。
ペイウォールは「2体目完成後」（1体目は無料体験を優先）。

### A⑤ Acquisition
ASO: 「ぬりパズ 動物」「宝石パズル 癒し」「動物 コレクション ゲーム」。スクショ1枚目は動物園全景。

# 2. 設計フェーズ

## Step1 技術スタック
Flutter/Dart 3.x + Riverpod + Firebase(Firestore/Auth/Analytics/Crashlytics/Remote Config/Cloud Functions)
+ RevenueCat + Lottie。画面数8前後 → **MVVM採用**。

## Step2 画面フロー設計
```
起動 → オンボ(3枚・スキップ可) → 通知許可プレプロンプト（「お世話を忘れずに」訴求）
     → ホーム(動物園・所持動物一覧・群れ演出表示)
     → [パズル挑戦] → 固定簡単配色 → ジェムパズル本体
       → 完成 → Lottie完成演出 → 動物1アクション(鳴く/瞬き) → 図鑑登録 → なつき度Lv1
     → [動物詳細] → 交流(エサ/なでる/遊ぶ・日替わりランダム) → 個性リアクション演出
       → なつき度Lv上昇時は専用アニメ
     → [図鑑] → コンプ進捗・群れ揃い判定 → ミニシーン再生
     → [シェア] → 動物園全景スクショ生成 → SNS共有シート
     → [設定] → 通知／サウンド／サブスク管理
```
Aha Momentへの最短経路（起動→パズル→完成→動物アクション=3タップ以内）を最優先。

## Step3 データモデル
```
User { uid, plan(free/pro), streakDays, lastVisitAt, createdAt }
AnimalMaster { id, name, habitat, personalityTag, pixelArtId, rarity, reactionSetId }
UserAnimal { uid, animalId, unlockedAt, affectionLevel(1-4), lastInteractedAt, isDeclineWarned }
PuzzleSession { id, uid, animalId, startedAt, completedAt, mistakeCount }
HerdBonus { uid, habitat, completedCount, sceneUnlockedAt }
ShareAsset { id, uid, generatedAt, imageUrl }
```
入稿パイプライン: 動物マスタ(pixelArt・性格タグ・リアクション演出)はスプレッドシート→検証スクリプト
（重複・NGワード）→Firestore投入。petit_ai活用時は生成後に同パイプラインへ合流。

## Step4 API仕様
外部API連携なし。動物リアクション演出はクライアント内Lottie切替のみ（オフライン交流も可）。

## Step4.5 計測設計
```
必須3点: Firebase Analytics / Crashlytics / Remote Config
KPIイベント(5個以内): aha_moment_reached(初回動物アクション) / animal_interacted(なつき度更新)
                      / herd_bonus_unlocked / share_created / paywall_converted
なつき度低下率をチャーン先行指標として追加監視（Remote Configでしきい値調整可）
```

## Step5 セキュリティ・パフォーマンス
APIキー環境変数／HTTPS／なつき度・所持動物データはFirestoreルールでクライアント直接書込み制限、
交流はCloud Functions経由（改ざん対策）／タイムアウト10秒・リトライ3回／パズル・図鑑・交流演出はフルオフライン対応。

## Step5.5 UI/UXクオリティ設計

# 3. 批判的レビュー＋メタレビュー

## 致命的リスク候補
**① Jewel Coloring対比で「絵柄の物量」が構造的に不利**
競合は1,000関卡以上を既に保有。petit_aiでの絵柄自動生成が実運用に乗るかが生命線であり、未検証。

**② 育成要素が浅いと「Jewel Coloringの下位互換」に見える**
→ なつき度Lv制＋個性反応＋群れ演出の詳細設計により一定解消済み（本書「なつき度・育成システム」参照）。

## 6軸評価
| 軸 | 評価 | コメント |
|---|---|---|
| 1. 魅力・楽しさ | △ | パズル単体では先発に勝てない。育成の作り込みが生命線 |
| 2. 継続性 | △ | ①のコンテンツ物量問題が長期的に効く |
| 3. ビジネス性 | ○ | 広告主体＋コスメ課金は妥当。ARPUは低めになりやすい |
| 4. スコープ | ○ | Must5個は妥当 |
| 5. 市場 | ○ | Jewel Coloring人気＝ニーズ実証済み |
| 6. KPI現実性 | ○ | ベンチマーク範囲内 |

## メタレビュー
Day7 18%はJewel Coloring層の流入前提の強気設定。育成要素が浅い場合はより保守的な15%を見込むべき。
白地の強さは「育成」の作り込み1点に依存する構造的な脆さがある。
